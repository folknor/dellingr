## Confirmed findings

### C11. Several Lua 5.2 short-string escapes decode incorrectly

- **Severity:** Medium-low
- **Locations:** `src/compiler/parser.rs:253`, especially `:279`;
  `src/compiler/lexer.rs:334`
- **Cause:** Decimal escapes, hexadecimal escapes, and whitespace-eating
  `\z` are not fully parsed.
- **Reproduction:** `#"\065"` and `#"\x41"` produce lengths 3 and 4 rather
  than 1; a multiline `\z` case is rejected.
- **Suggested regression:** Lexer/parser unit tests and differential cases.

### C12. Unsupported long strings cross the public `Result` boundary as panic

- **Severity:** Low
- **Location:** `src/compiler/lexer.rs:176`
- **Cause:** Encountering `[[` or `[=` invokes `panic!` rather than returning
  a syntax/unsupported error.
- **Reproduction:** `print([[hello]])` makes the CLI exit 101.
- **Suggested regression:** Lexer and public compilation no-panic tests.

### C13. Static minimum cost overstates an empty dynamic `SetList`

- **Severity:** Low
- **Locations:** `src/lib.rs:130`; runtime accounting in
  `src/vm/frame.rs:365`
- **Cause:** Static analysis assigns cost 1 to dynamic `OP_SET_LIST`, while an
  execution with no expanded values charges zero for that operation.
- **Reproduction:** Construct `{...}` in a function and invoke it with no
  arguments. Runtime total is 1; static output states a minimum of 2.
- **Suggested regression:** `analyze_cost` unit test.

### C23. Invalid CLI `--limit` silently disables the budget

- **Severity:** Medium
- **Location:** `src/main.rs:29`
- **Cause:** A parse failure warns, sets the limit to `None`, and continues
  execution successfully.
- **Reproduction:** `dellingr --limit nope script.lua` runs the script without
  a budget and exits zero.
- **Suggested regression:** CLI integration cases for malformed, missing,
  negative, and valid limits.

### C24. Cost batching permits operations beyond the documented budget boundary

- **Severity:** Medium
- **Locations:** `src/vm/frame.rs:139`, cost dispatch at `:295`; budget
  contract in `src/vm.rs:295`, `:315`
- **Cause:** Opcode charges accumulate locally and flush only every 64 cost
  units. After a flush makes the remaining budget negative, a fresh batch can
  execute up to 63 additional costed operations before the next check.
- **Reproduction:** A script with 65 `x=x+1` statements under `--limit 63`
  prints `65`, then reports that 64 cost exceeded the budget. The operation
  after the one that exhausted the budget should not execute.
- **Suggested regression:** Assert the exact side-effect boundary in
  `tests/error_handling.rs`, including budgets not divisible by 64.

### C25. String-only allocation never triggers automatic GC

- **Severity:** High
- **Locations:** Allocation check in `src/vm.rs:635`;
  `GcHeap::is_full` in `src/vm/object.rs:345`
- **Cause:** Automatic collection checks only the GC object count. Interned
  strings are swept only when object-driven collection happens, but string
  count does not contribute to that threshold.
- **Reproduction:** With threshold 20, allocate 1,000 distinct temporary
  strings in `State::empty()`. The public API reports 1 object and 1,001
  strings afterward; no automatic collection occurred.
- **Suggested regression:** A string-only automatic-collection test with a
  small threshold in `src/vm/tests.rs` or `tests/gc_upvalues.rs`.

### C27. Loading a snapshot of `State::empty()` installs standard libraries

- **Severity:** High
- **Locations:** Empty construction in `src/vm.rs:243`; loading in
  `src/vm/save_state.rs:433`; library installation in `src/vm.rs:215`
- **Cause:** `load_state` always constructs its destination through
  `State::with_callbacks`, which installs libraries. The snapshot does not
  record that its source was an empty environment and has no globals that
  remove the newly installed ones.
- **Reproduction:** Save `State::empty()`, load it, then read global `math`.
  The loaded state contains the math table instead of nil.
- **Suggested regression:** Snapshot round trip for an empty state in
  `tests/save_state.rs`, including representative builtins.

## Unresolved leads

- **L1 - Dynamic argument-count overflow:** `State::call` casts a dynamic
  stack-derived count to `u8` at `src/vm/eval.rs:39`. Expansions beyond 255
  may wrap and misframe calls; not separately reduced.
- **L2 - Meaning of nested static costs:** `ScopeCost::total_cost` sums nested
  function bodies even when never invoked (`src/lib.rs:148`), while CLI output
  calls the value a minimum. Documentation/intent is unclear.
- **L3 - Permissive table separators:** Constructors accept leading separators
  such as `{,1}` and `{;}` at `src/compiler/parser/table.rs:67`, unlike Lua
  5.2/5.4. Intent is unclear.
- **L4 - Frontier matcher one-past-end read:**
  `src/patterns/luapat.rs:377` dereferences the current position when it may
  equal `src_end`. The reviewer did not complete a sanitizer or Miri run.
- **L5 - Cross-platform math determinism:** Transcendentals in
  `src/lua_std/math.rs` use platform `f64` implementations. Whether replay
  determinism extends across architectures/libm implementations needs an
  explicit contract decision.
- **L6 - Direct host callback error notification:** `HostCallbacks::on_error`
  is invoked for Rust-function failures reached from Lua but not necessarily
  when the host directly calls a failing Rust function. Trait intent is
  ambiguous.
- **L7 - `string.format` error contract:** Missing/wrong-typed values can be
  omitted and unsupported conversions preserved instead of raising Lua-style
  errors. The implementation is visibly partial, but the supported error
  contract is undocumented.
- **L8 - Dynamic-call-base cleanup after errors:** An argument-evaluation
  failure after `OP_MARK_CALL_BASE` may leave an obsolete entry because
  `eval_closure_inner` does not restore `vararg_call_bases`
  (`src/vm/eval.rs:293`). This may make an otherwise reusable snapshot-enabled
  State fail quiescence validation; a feature-gated reproduction is needed. The
  same applies to `table_constructor_bases` (added for C6): an error between
  `NewTableTracked` and `SetList(0)` leaves a stale base. A fix should capture
  each base stack's length on frame entry and truncate to that watermark on
  frame error, covering both stacks together.
- **L9 - Malformed public `State::call`:** Fixed argument counts can
  underflow stack arithmetic and Dynamic uses `expect`
  (`src/vm/eval.rs:34`). The documented caller protocol may place malformed
  calls outside the API contract.
- **L10 - Engine-version compatibility in snapshots:** The decoder reads but
  does not compare the saved engine-version string
  (`src/vm/save_state.rs:438`). Format compatibility is checked separately;
  cross-version behavior/bytecode compatibility needs a product-policy
  decision.
- **L11 - Restricted environment restoration after panic:**
  `with_restricted_env` restores globals for normal and error returns but has
  no unwind guard. Relevance depends on whether embedders may catch panics and
  reuse a State.
- **L12 - `gmatch` is a stateful iterator, not a Lua closure:** dellingr's
  `string.gmatch` returns `(iter, state_table)` and relies on the generic-`for`
  protocol; reference Lua returns a self-contained closure callable with no
  args. `local f = string.gmatch(s, p); f()` works in Lua but errors in
  dellingr ("table expected"). Surfaced while fixing C15/C17/C18.
- **L13 - Leading `^` in `gsub`/`gmatch`:** `string.gsub("aa", "^a", "X")`
  gives `XX, 2` (should be `Xa, 1` - `^` should anchor only the first attempt),
  and `gmatch` treats a leading `^` as an anchor although Lua 5.2 treats it
  literally there.
- **L14 - Pattern validator gaps (pattern-pointer, not subject-pointer):** the
  `str_match_check` validator does not skip both `%b` delimiter bytes (rejects a
  valid `%b((`), and some checks dereference `p` before testing `p == p_end`
  for malformed `[`, `(`, or `%f` endings. Separate from the subject-end guards
  added for C17.
- **L15 - Broader `gsub` replacement contract:** beyond the `%`-form grammar
  fixed in C18, numeric replacement values are not coerced to strings, invalid
  replacement types are silently retained rather than erroring, and a malformed
  pattern with replacement limit `0` errors eagerly whereas Lua returns the
  input unchanged (the pattern is never compiled when `max == 0`).
- **L16 - `tonumber` hex floats at extremes:** `parse_lua_numeral`
  (`src/numeral.rs`) handles ordinary hex floats but is not reference-exact for
  pathological ones - a huge binary exponent (`0x1p2147483648`) returns nil
  instead of inf, a tiny one (`0x1p-9999999999`) returns nil instead of 0, and
  a several-hundred-digit mantissa scaled back can yield NaN from `inf * 0`. A
  faithful fix needs bounded significant-digit accumulation with a saturating
  exponent. Added while fixing C19; ordinary cases are correct.
