# Bug hunt - 2026-07-23

This document consolidates and deduplicates findings from two waves of
independent, read-only audits. It records confirmed findings, unresolved
leads, and clean coverage. No fixes were made during the audit.

## Confirmed findings

### C1. Lexical-block closures can observe later locals

- **Severity:** High
- **Locations:** `src/compiler/parser.rs:301`; block exits in
  `src/compiler/parser/stmt.rs:429`, `:507`
- **Cause:** Leaving `do`/`if`/`elseif`/`else` scope forgets locals without
  closing their open upvalues. A later local can reuse the captured slot.
- **Reproduction:** Capture `local x=1` inside `do`, leave the block, declare
  another `local x=2`, then call the closure. Dellingr returns `2`; Lua 5.2
  returns `1`.
- **Suggested regression:** Parser close emission plus execution coverage in
  `tests/gc_upvalues.rs`.

### C2. Numeric and generic `for` closures capture reused/final loop slots

- **Severity:** High
- **Locations:** `src/compiler/parser/stmt.rs:280`, `:356`
- **Cause:** Per-iteration closing starts after the visible loop variables.
  Numeric closures all observe the final value; generic-loop termination can
  overwrite captured variables with nil.
- **Reproduction:** Store `function() return i end` on each iteration of
  `for i=1,3`. Dellingr returns `3,3,3`; Lua 5.2/5.4 returns `1,2,3`.
- **Suggested regression:** Numeric and generic loop cases in
  `tests/gc_upvalues.rs`.

### C3. `break` bypasses loop-local upvalue closing

- **Severity:** High
- **Locations:** Break patching in `src/compiler/parser.rs:325`; loop close
  paths in `src/compiler/parser/stmt.rs:301`, `:411`, `:453`, `:490`
- **Cause:** A break jumps past the normal back-edge `CloseUpvalues`.
- **Reproduction:** Capture a loop-local value, break, then reuse its slot
  after the loop. Dellingr returns the later value; Lua 5.2 retains the
  captured value.
- **Suggested regression:** `tests/gc_upvalues.rs`.

### C4. Exactly 255 explicit call arguments collide with `Dynamic`

- **Severity:** High
- **Locations:** `src/compiler/parser/expr.rs:14`, `:239`;
  `src/instr.rs:11`; panic observed at `src/vm/eval.rs:38`
- **Cause:** `ArgCount::Fixed(255)` and `ArgCount::Dynamic` share byte value
  255. Code generation removes the fixed-call base marker, while execution
  decodes the call as dynamic and expects that marker.
- **Reproduction:** Call a vararg function with exactly 255 literal
  arguments. Compilation succeeds and execution panics instead of making the
  valid call.
- **Suggested regression:** Parser boundary test and public API no-panic test.

### C5. 256 function parameters wrap the parameter count

- **Severity:** High
- **Locations:** `src/compiler/parser/func.rs:113`;
  `src/compiler/parser.rs:394`, `:487`
- **Cause:** An unbounded parameter count is cast to `u8`; 256 becomes zero
  while local slot indices also wrap.
- **Reproduction:** Define a function with 256 parameters and invoke it.
  Compilation succeeds, then execution panics in `src/vm/eval_index.rs`.
- **Suggested regression:** Compiler limit test and public API no-panic test.

### C6. Final table list fields use incorrect multi-value rules

- **Severity:** Medium-high
- **Location:** `src/compiler/parser/table.rs:64`, `:116`
- **Cause:** A final function call is forced to one result, while a non-final
  vararg expression expands to all results. Lua expands only the final list
  field when it is a call or vararg.
- **Reproduction:** `{7, f()}` with `f` returning `11,22,33` has length 2
  instead of 4. `{...,99}` expands all varargs instead of retaining one.
- **Suggested regression:** Parser-bytecode tests and table-constructor
  execution tests.

### C7. Non-local assignment fails to expand a tail vararg

- **Severity:** Medium
- **Location:** `src/compiler/parser/stmt.rs:83`
- **Cause:** Assignment adjusts a tail function call to fill remaining
  lvalues but does not perform the equivalent adjustment for `ExpDesc::Vararg`.
- **Reproduction:** Within a vararg function, `a,b=...` called with `11,22`
  produces `11,nil` instead of `11,22`.
- **Suggested regression:** Parser and assignment execution tests.

### C8. Generic-for setup fails to expand a tail vararg

- **Severity:** Medium
- **Location:** `src/compiler/parser/stmt.rs:359`
- **Cause:** Generic-for setup expands a final call into the iterator triple
  but treats a final vararg as one value and pads the remaining values with
  nil.
- **Reproduction:** Inside a vararg function, iterate using
  `for x in ... do`; passing `iterator,state,control` yields a nil-state error
  instead of iterating.
- **Suggested regression:** Parser and generic-for execution tests.

### C9. Long branches silently overflow signed 16-bit jump offsets

- **Severity:** Medium
- **Locations:** Unchecked jump casts throughout
  `src/compiler/parser/stmt.rs`, including `:307`, `:419`, `:459`, `:495`,
  `:533`, `:562`; short-circuit offsets in
  `src/compiler/parser/expr.rs:34`
- **Cause:** Offsets greater than 32767 are cast from `usize` to `i16` and
  wrap negative.
- **Reproduction:** Put 17,000 assignments in a false `if` branch. Compilation
  succeeds, then execution reports an internal invalid-jump error.
- **Suggested regression:** Boundary compiler test around a shared checked
  jump-patching helper.

### C10. 256 field-assignment sites panic during cache finalization

- **Severity:** Medium
- **Location:** `src/compiler.rs:214`, especially `:246`, `:259`
- **Cause:** Each `OP_SET_FIELD` site receives a unique `u8` cache slot;
  checked conversions end in `expect` rather than a fallback or compiler
  error.
- **Reproduction:** Compile a table declaration followed by 256 `t.x=nil`
  statements. Compilation panics.
- **Suggested regression:** Compile boundary cases at 255 and 256 sites.

### C11. Several Lua 5.2 short-string escapes decode incorrectly

- **Severity:** Medium-low
- **Locations:** `src/compiler/parser.rs:253`, especially `:279`;
  `src/compiler/lexer.rs:334`
- **Cause:** Decimal escapes, hexadecimal escapes, and whitespace-eating
  `\z` are not fully parsed.
- **Reproduction:** `#"\065"` and `#"\x41"` produce lengths 3 and 4 rather
  than 1; a multiline `\z` case is rejected.
- **Suggested regression:** Lexer/parser unit tests and differential cases.

### C12. Unsupported long strings cross the public `Result` boundary as panic

- **Severity:** Low
- **Location:** `src/compiler/lexer.rs:176`
- **Cause:** Encountering `[[` or `[=` invokes `panic!` rather than returning
  a syntax/unsupported error.
- **Reproduction:** `print([[hello]])` makes the CLI exit 101.
- **Suggested regression:** Lexer and public compilation no-panic tests.

### C13. Static minimum cost overstates an empty dynamic `SetList`

- **Severity:** Low
- **Locations:** `src/lib.rs:130`; runtime accounting in
  `src/vm/frame.rs:365`
- **Cause:** Static analysis assigns cost 1 to dynamic `OP_SET_LIST`, while an
  execution with no expanded values charges zero for that operation.
- **Reproduction:** Construct `{...}` in a function and invoke it with no
  arguments. Runtime total is 1; static output states a minimum of 2.
- **Suggested regression:** `analyze_cost` unit test.

### C15. Position captures panic instead of returning an index

- **Severity:** High
- **Locations:** `src/patterns/luapat.rs:465`;
  `src/lua_std/string.rs:45`
- **Cause:** A position capture is encoded as a sentinel range, but stdlib
  wrappers treat every capture as a byte range and slice with its invalid
  start.
- **Reproduction:** `string.match("abc", "()")` panics with a range starting
  at `usize::MAX`; Lua 5.2/5.4 returns `1`.
- **Suggested regression:** Matcher and public `match`/`find`/`gmatch`/`gsub`
  position-capture tests at start, middle, and end.

### C16. A very large host cost charge increases the remaining budget

- **Severity:** High
- **Location:** `src/vm.rs:321`
- **Cause:** Public `consume_cost(u64)` casts the charge to `i64` before
  subtraction. Values above `i64::MAX` become negative; `cost_used` can also
  overflow.
- **Reproduction:** With budget 1, `consume_cost(u64::MAX)` leaves remaining
  budget 2 and used cost `u64::MAX`.
- **Suggested regression:** Public API boundary tests at `i64::MAX`,
  `i64::MAX + 1`, and `u64::MAX`.

### C17. Valid zero-width matches at end-of-input are rejected

- **Severity:** Medium
- **Locations:** `src/lua_std/string.rs:261`, `:540`;
  `src/patterns/luapat.rs:593`
- **Cause:** Wrappers reject `init == len`, and the unanchored matcher never
  tries the one-past-last position.
- **Reproduction:** `string.find("", "$")`, `string.match("", "$")`, and
  `string.find("abc", "$", 4)` all return nil. Lua 5.2 returns the expected
  empty end matches.
- **Suggested regression:** Extend the empty-pattern/init-bound tests in
  `tests/string_bytes.rs`.

### C18. Malformed patterns and replacements are silently accepted

- **Severity:** Medium
- **Locations:** `src/lua_std/string.rs:73`, `:286`, `:555`, `:723`, `:819`
- **Cause:** Matcher-construction errors are converted to nil or unchanged
  input, while invalid replacement `%` forms and unavailable captures are
  copied or dropped rather than reported.
- **Reproduction:** `string.match("abc", "[")` returns nil;
  `string.gsub("a", "a", "%q")` returns `%q,1`. Lua 5.2 reports errors.
- **Suggested regression:** `tests/gsub_errors.rs` and malformed
  `find`/`match`/`gmatch` cases in `tests/string_bytes.rs`.

### C19. Default numeric conversion rejects Lua forms and accepts `NaN`

- **Severity:** Medium
- **Location:** `src/lua_std/basic.rs:198`
- **Cause:** `tonumber` delegates directly to Rust `str::parse::<f64>()`,
  without Lua whitespace/hex rules and with Rust-only spellings.
- **Reproduction:** `tonumber(" 42 ")` and `tonumber("0x10")` return nil,
  while `tonumber("NaN")` returns NaN. Lua 5.2 returns `42`, `16`, and nil.
- **Suggested regression:** Extend numeric-conversion cases in
  `tests/error_handling.rs`.

### C20. `__metatable` does not protect metatables

- **Severity:** Medium
- **Location:** `src/lua_std/basic.rs:276`
- **Cause:** `getmetatable` exposes the raw table and `setmetatable` replaces
  it without consulting the existing `__metatable` field.
- **Reproduction:** A table whose metatable contains
  `__metatable="locked"` can still reveal and replace that metatable.
- **Suggested regression:** `tests/metamethod_errors.rs`.

### C21. Several stdlib entry points accept invalid calls as success

- **Severity:** Medium
- **Locations:** `src/lua_std/table.rs:28`, `:243`;
  `src/lua_std/math.rs:163`
- **Cause:** `table.insert` lacks a too-few-arguments error path;
  `table.move` treats a non-table explicit destination as omitted; invalid
  `math.random` intervals return nil.
- **Reproduction:** Invalid calls complete with plausible values or write to
  the source table, while the applicable Lua reference reports argument/range
  errors.
- **Suggested regression:** Arity, type, and interval failures in
  `tests/error_handling.rs`.

### C22. Rebinding global `next` breaks `pairs`

- **Severity:** Low
- **Location:** `src/lua_std/basic.rs:98`
- **Cause:** `pairs` fetches the mutable global named `next` rather than
  returning the builtin iterator.
- **Reproduction:** After `next=42`, iterating `pairs({a=1})` attempts to call
  the number. Lua 5.2 still iterates normally.
- **Suggested regression:** Add near existing `ipairs` coverage.

### C23. Invalid CLI `--limit` silently disables the budget

- **Severity:** Medium
- **Location:** `src/main.rs:29`
- **Cause:** A parse failure warns, sets the limit to `None`, and continues
  execution successfully.
- **Reproduction:** `dellingr --limit nope script.lua` runs the script without
  a budget and exits zero.
- **Suggested regression:** CLI integration cases for malformed, missing,
  negative, and valid limits.

### C24. Cost batching permits operations beyond the documented budget boundary

- **Severity:** Medium
- **Locations:** `src/vm/frame.rs:139`, cost dispatch at `:295`; budget
  contract in `src/vm.rs:295`, `:315`
- **Cause:** Opcode charges accumulate locally and flush only every 64 cost
  units. After a flush makes the remaining budget negative, a fresh batch can
  execute up to 63 additional costed operations before the next check.
- **Reproduction:** A script with 65 `x=x+1` statements under `--limit 63`
  prints `65`, then reports that 64 cost exceeded the budget. The operation
  after the one that exhausted the budget should not execute.
- **Suggested regression:** Assert the exact side-effect boundary in
  `tests/error_handling.rs`, including budgets not divisible by 64.

### C25. String-only allocation never triggers automatic GC

- **Severity:** High
- **Locations:** Allocation check in `src/vm.rs:635`;
  `GcHeap::is_full` in `src/vm/object.rs:345`
- **Cause:** Automatic collection checks only the GC object count. Interned
  strings are swept only when object-driven collection happens, but string
  count does not contribute to that threshold.
- **Reproduction:** With threshold 20, allocate 1,000 distinct temporary
  strings in `State::empty()`. The public API reports 1 object and 1,001
  strings afterward; no automatic collection occurred.
- **Suggested regression:** A string-only automatic-collection test with a
  small threshold in `src/vm/tests.rs` or `tests/gc_upvalues.rs`.

### C26. `table.insert` accepts out-of-range and non-integral positions

- **Severity:** Medium
- **Locations:** `src/lua_std/table.rs:42`;
  `src/vm/table_ops.rs:243`; `src/vm/table.rs:410`
- **Cause:** Position validation checks only for numeric type, then casts with
  `as usize`. Position zero is accepted by the underlying insertion routine,
  which shifts sequence keys, writes key zero, and advances cached length.
- **Reproduction:** Insert `5` at position zero in `{10,20}`. Dellingr
  produces length 3 with `t[0]=5`, `t[1]=nil`; Lua 5.4 reports a bounds error.
  Negative, fractional, NaN, and oversized positions need the same validation.
- **Suggested regression:** Invalid position cases in
  `tests/error_handling.rs`; audit equivalent conversion in `table.remove`.

### C27. Loading a snapshot of `State::empty()` installs standard libraries

- **Severity:** High
- **Locations:** Empty construction in `src/vm.rs:243`; loading in
  `src/vm/save_state.rs:433`; library installation in `src/vm.rs:215`
- **Cause:** `load_state` always constructs its destination through
  `State::with_callbacks`, which installs libraries. The snapshot does not
  record that its source was an empty environment and has no globals that
  remove the newly installed ones.
- **Reproduction:** Save `State::empty()`, load it, then read global `math`.
  The loaded state contains the math table instead of nil.
- **Suggested regression:** Snapshot round trip for an empty state in
  `tests/save_state.rs`, including representative builtins.

## Unresolved leads

- **L1 - Dynamic argument-count overflow:** `State::call` casts a dynamic
  stack-derived count to `u8` at `src/vm/eval.rs:39`. Expansions beyond 255
  may wrap and misframe calls; not separately reduced.
- **L2 - Meaning of nested static costs:** `ScopeCost::total_cost` sums nested
  function bodies even when never invoked (`src/lib.rs:148`), while CLI output
  calls the value a minimum. Documentation/intent is unclear.
- **L3 - Permissive table separators:** Constructors accept leading separators
  such as `{,1}` and `{;}` at `src/compiler/parser/table.rs:67`, unlike Lua
  5.2/5.4. Intent is unclear.
- **L4 - Frontier matcher one-past-end read:**
  `src/patterns/luapat.rs:377` dereferences the current position when it may
  equal `src_end`. The reviewer did not complete a sanitizer or Miri run.
- **L5 - Cross-platform math determinism:** Transcendentals in
  `src/lua_std/math.rs` use platform `f64` implementations. Whether replay
  determinism extends across architectures/libm implementations needs an
  explicit contract decision.
- **L6 - Direct host callback error notification:** `HostCallbacks::on_error`
  is invoked for Rust-function failures reached from Lua but not necessarily
  when the host directly calls a failing Rust function. Trait intent is
  ambiguous.
- **L7 - `string.format` error contract:** Missing/wrong-typed values can be
  omitted and unsupported conversions preserved instead of raising Lua-style
  errors. The implementation is visibly partial, but the supported error
  contract is undocumented.
- **L8 - Dynamic-call-base cleanup after errors:** An argument-evaluation
  failure after `OP_MARK_CALL_BASE` may leave an obsolete entry because
  `eval_closure_inner` does not restore `vararg_call_bases`
  (`src/vm/eval.rs:293`). This may make an otherwise reusable snapshot-enabled
  State fail quiescence validation; a feature-gated reproduction is needed.
- **L9 - Malformed public `State::call`:** Fixed argument counts can
  underflow stack arithmetic and Dynamic uses `expect`
  (`src/vm/eval.rs:34`). The documented caller protocol may place malformed
  calls outside the API contract.
- **L10 - Engine-version compatibility in snapshots:** The decoder reads but
  does not compare the saved engine-version string
  (`src/vm/save_state.rs:438`). Format compatibility is checked separately;
  cross-version behavior/bytecode compatibility needs a product-policy
  decision.
- **L11 - Restricted environment restoration after panic:**
  `with_restricted_env` restores globals for normal and error returns but has
  no unwind guard. Relevance depends on whether embedders may catch panics and
  reuse a State.
